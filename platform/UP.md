# Подъем платформы

## Настройки и запуск

Нужны Docker с Linux-контейнерами, kind, kubectl, Helm, Bash и curl с поддержкой `--aws-sigv4`.

Скрипт сначала выполняет `source .env.example`, затем `source .env`, если файл существует. **.env перекрывает учебные значения.** Отдельного приоритета переменных окружения и CLI-флагов нет. Это обычные доверенные Bash-файлы: не загружай чужой .env, поскольку source способен выполнять команды.

Свой .env создавать необязательно. Если нужен, не перезаписывай существующий:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Из Git Bash, Linux или macOS:

```bash
bash platform/up.sh
```

В PowerShell на этом компьютере Git Bash установлен здесь:

```powershell
& "D:\Work\Git\bin\bash.exe" platform/up.sh
```

На другом компьютере путь может отличаться. Системный bash.exe в Windows может запускать WSL — используй именно Git Bash.

## Что происходит по порядку

1. Читаются настройки, проверяются инструменты и доступ к Docker.
2. Создается kind-кластер, если его нет; выбирается его kubeconfig. Порт 80 задается при создании через kind-config.yaml.
3. Уже скачанные образы переносятся архивом одной платформы. Если их нет или перенос не удался, kubelet скачает их из registry.
4. Применяется MLflow с namespace mlops и PVC. Создается S3 Secret; применяются RustFS и Airflow.
5. Helm устанавливает/обновляет Traefik, Prometheus/Grafana и metrics-server. Последний нужен существующему HPA по CPU.
6. Применяется Ingress, ожидается готовность платформы.
7. Создается бакет pred-main-dvc и проверяется подписанным HEAD. После 30 неуспешных попыток скрипт завершается с ошибкой, а не пишет «готово».

## Креды и ограничения

- S3-ключи из файла попадают в Secret mlops/s3-credentials. Его используют RustFS и задачи Airflow. Для локального DVC credentials настраиваются отдельно по Quickstart.
- Бакет и endpoints должны совпадать с .dvc/config и Ingress. Их произвольное переименование одной переменной не поддерживается.
- Grafana использует admin/admin из platform/monitoring-values.yaml. Свои значения настраиваются там вручную.
- DB_PASSWORD в шаблоне — договоренность для первого deploy. Такое же значение нужно задать GitHub Secret DB_PASSWORD в своем репозитории/форке. up.sh PostgreSQL и его Secret не создает.
- Токен регистрации runner вводится отдельно, в шаблон не записывается.
- Скрипт не удаляет кластер, PVC или данные, но повторный Helm upgrade может заменить pod.
- **При повторном запуске сохраняй прежние credentials.** Изменение файла не является процедурой ротации работающих сервисов; скрипт не проверяет этот конфликт.
- У существующего кластера нельзя изменить проброс порта простым повторным запуском.
- Удаление kind может уничтожить локальные PVC; перед чистым прогоном отдельно сохраняем данные и доказательства.

## После платформы — вручную по README

Получить датасет, настроить локальный DVC, загрузить данные в S3, обучить первого champion, зарегистрировать свой runner, задать GitHub Secret и выполнить deploy API. Затем проверить ответ через Ingress и запуск DAG.

`up.sh` не выполняет эти шаги и не означает готовность API. Полный Quickstart еще предстоит проверить с нуля. Скрипт проверен синтаксически, но против рабочего кластера при этой правке не запускался.
